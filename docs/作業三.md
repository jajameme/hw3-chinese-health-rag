日期：2026-10-25。依 [作業三實作計畫](../plan/作業三實作計畫：RAG%20健康諮詢小幫手.md) 開始實作，專案位於 [專案根目錄](../README.md)。長時間的安裝、下載、爬取、摘要、索引與展示皆由背景程序執行，查詢入口是 [state.json 完成快照](../results/pipeline_state.json)。本文件把規劃與已實測的結果分開記錄，尚在背景執行的步驟不視為已完成。

## 實作方式

以課堂 [cases/RAG](https://github.com/telunyang/python_nlp/tree/main/cases/RAG) 與 [cases/ollama](https://github.com/telunyang/python_nlp/tree/main/cases/ollama) 為參考，拆成可獨立執行且能接續的工作：

| 步驟 | 程式與做法 |
| --- | --- |
| 環境 | 專案獨立 Python 3.12 `.venv`，PyTorch 2.11.0 CUDA 12.8；其餘核心套件固定為計畫指定版本 |
| 地端服務 | `runtime.py` 下載官方 Ollama Windows 可攜版、驗證 release SHA256，存於 `.tools`，模型存於 `.cache/ollama`；只監聽 loopback |
| 列表 | `crawl_list.py` 對三個分類以輪流分頁方式蒐集連結，最多每分類 6 頁、120 個不重複連結，列表頁快取可接續 |
| 文章 | `crawl_articles.py` 擷取全文、發布日、分類與標題，每篇立即寫回 SQLite；URL UNIQUE 防重，失敗留清單，下次跳過已成功的文章 |
| 摘要 | `summarize.py` 將標題和前 3000 字送給本機 Gemma，要求約 180–230 字繁體中文、單段摘要；不補寫醫療事實，每篇完成即 commit |
| 索引 | `make_index.py` 先卸載此專案的 Ollama 模型，才以 bge-m3 GPU batch 8 向量化摘要；正規化向量配 `IndexIDMap(IndexFlatIP)`，使用 news.id 作 ID，每次重建 |
| 檢索 | `rag.py` 在 CPU 載入 bge-m3，top-3／門檻 0.45；檢查摘要 fingerprint 與索引 SHA256，避免資料和向量不同步 |
| 多輪問答 | `app.py` 以 Flask SSE 串流，SQLite 依瀏覽器 session 分開保存歷史；checkbox 決定本輪是否檢索 |
| 來源 | 由程式附加資料庫中的標題、連結、發布日；不檢索時使用先前對話來源並註明，沒有來源時直接說明不足，不讓模型補造連結 |
| 網頁 | `templates/index.html`、`static/style.css`、`static/chat.js`，支援行動版、來源卡片、狀態提示與清除自己的歷史 |
| 展示 | `evaluate.py` 實際做標題檢索檢查，再生成兩輪不同分類的新聞問題與一輪關閉檢索的重點整理，輸出 JSON、Markdown、逐字稿排版圖片 |

## 已完成的調查與調整

1. 實際讀取健康醫療網的 robots.txt：目前一般 User-Agent 僅排除 `/rss_file/`，本案只抓公開分類和文章頁，請求間隔 3–8 秒。已抽查分類頁 `li.list-item` 和文章 `#article-title`、`#article-content`，選取器仍可用。發布日優先讀 `meta[property="article:published_time"]`，不是擷取報導人名時順帶猜測日期。
2. 選擇「醫療疾病、健康保健、營養飲食」三類。已確認公開分類 URL，移除老師範例僅篩「大腸」的條件。單篇抓取時拒絕外站 URL、空白內容或無法確認發布日的文章。
3. 本機尚未安裝 Ollama，所以以官方可攜版放進工作區，避免需要手動系統安裝。2026-10-25 查得官方 release 為 v0.40.11；下載程式保留實際版本與 SHA256 至 `.tools/ollama-release.json`。
4. 將模型明確設定為 [`gemma4:e2b-it-q4_K_M`](https://ollama.com/library/gemma4:e2b-it-q4_K_M)，而非可能改變內容的 `gemma4:e2b` 標籤；官方頁面目前列出約 4.6 GB。實際 GPU／CPU 配置仍須等下載完成後用 Ollama 的執行資訊確認，不能預先假設全部在 GPU。
5. 本機是 GTX 1660 Ti 6 GB；bge-m3 建索引時先卸載 Gemma，線上檢索固定 CPU，避免兩個模型爭用 GPU。摘要前 3000 字、context 4096，長文後段可能沒被涵蓋，屬本版摘要的限制。

修正為要求回答約 250–350 個中文字、最多五點，問答輸出上限提高至 1200 tokens；若仍遇 `done_reason=length`，以同一批資料加上更精簡的要求重試一次。重試仍截斷則保持失敗，且不寫入半截歷史。網頁串流採相同原則，重試後以完整新回答取代已顯示的暫存文字；未收到完成標記的串流也會報錯。

新增四個回歸測試，確認截斷後可重新生成、重試不改寫原問題、連續超限不寫歷史、沒有完成標記不接受，以及串流重試只保存完整新回答（涵蓋於四個測試中）；總計 10 個測試全部通過。背景監控新增 `--from-stage`，已從 evaluate 接續，保留先前完成步驟，無須重新下載、爬取、摘要或建索引。舊網頁程序已停止，背景評估完成後會啟動新版服務。

`results/evaluation.json` 的標題查詢 hit@3 只檢查索引與檢索管線，不能當作獨立的健康回答正確率。須檢視三輪逐字稿，確認回答與摘要相符、第三輪沒有重新檢索卻保留兩個主題、每輪有可回查的標題／連結／時間，並評估生成摘要是否遺漏風險或限制。所有回答僅供新聞閱讀，不能取代醫師診斷。
